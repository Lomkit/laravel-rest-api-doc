---
title: Confirmation
description: Make the endpoint check that the user confirmed an action before it runs, with a signed token and a 428 response.
---

`->confirm()` only asks clients to show a dialog: a client that skips it still runs the action. When an action must not run unconfirmed, declare `confirmation()`. The endpoint then answers `428` with a signed token, and runs the action only when the same request comes back with that token.

## Asking for a confirmation

`confirmation()` receives the fields and the number of rows the action would run on. Return an `ActionConfirmation` to ask, or `null` to run at once:

```php
use Lomkit\Rest\Actions\ActionConfirmation;
use Lomkit\Rest\Actions\ActionFields;

class ShredDocuments extends Action
{
    public function confirmation(ActionFields $fields, int $rows): ?ActionConfirmation
    {
        if ($rows < 3) {
            return null;
        }

        return ActionConfirmation::make("Shred {$rows} documents?")
            ->data(['rows' => $rows])
            ->expiresIn(300);
    }
}
```

- `make()` takes the message of the response.
- `data()` adds an object for the client. It takes an array with string keys, `{}` when empty. A list throws `Lomkit\Rest\Exceptions\InvalidActionException`.
- `expiresIn()` sets the lifetime of the token in seconds, `300` by default, at least `1`.
- `$rows` counts the rows that the search matches in the perimeter, within its `limit`, the keys of the `Resources` target, or `0` for the `None` target. It is counted before `skipUnauthorized()` leaves rows out, so `impacted` can end lower.

## The first request

```http
POST /api/documents/actions/shred-documents
```

```json
{}
```

The endpoint validates the body, runs the entry checks and the [row checks](/actions-and-metrics/actions#checking-each-row), then answers `428` and runs nothing:

```json
{
  "message": "Shred 4 documents?",
  "confirmation": {
    "token": "1794132300.1fd50fa4edba5784fb3ac2b71662fcbc9be3b716fba0383ddd6a4b6dd652bfb1",
    "expires_at": "2026-11-08T10:05:00Z",
    "data": {"rows": 4}
  }
}
```

No `operating()` event, no `handle()`, no job, no batch and no `ActionOperated` event run before the confirmation. A `422` and a `403` still come first.

## Confirming

The client sends the same body again, with the token under `confirmation`:

```json
{"confirmation": "1794132300.1fd50fa4edba5784fb3ac2b71662fcbc9be3b716fba0383ddd6a4b6dd652bfb1"}
```

```json
{"data": {"impacted": 4, "result": null}}
```

The token is valid for the same user and guard, the same resource and action, the same `search`, `resources` and `fields`, and the same number of rows, until it expires. It can be used again until then.

- The order of the keys and the unknown keys at the first level of the body do not count.
- Any other token, an expired one, or a number of rows that changed answers a new `428` with a fresh token. With one more row, the message becomes `Shred 5 documents?`.
- `confirmation` must be a string: another type, `null` included, is a `422`, `The confirmation field must be a string.`

::note
The token holds no state: it is signed with `app.key`. Set `APP_KEY` before an action asks for a confirmation. An empty key throws `Lomkit\Rest\Exceptions\InvalidConfigException` once a confirmation is due. An action whose `confirmation()` returns `null` needs no key.
::

## Clients

- The [details](/digging-deeper/details), with `?with=actions`, give `"confirmation": true` on each action that declares `confirmation()`. Show your dialog when the endpoint answers `428`, with the `message` and the `data` of the response.
- A [Precognition](/digging-deeper/precognition) request stops before the confirmation: it answers `204` or `422` and asks nothing.
- The OpenAPI document lists the `428` response, `RestConfirmationRequired`, on the operations of these actions, and documents `confirmation` in their body. See [OpenAPI](/digging-deeper/openapi).
