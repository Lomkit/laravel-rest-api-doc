## Defining a resource

A resource declares what the API exposes for one Eloquent model. Resources live in `app/Rest/Resources` and extend your base resource, `app/Rest/Resources/Resource.php`, which extends `Lomkit\Rest\Http\Resource`.

```php [app/Rest/Resources/ProductResource.php]
namespace App\Rest\Resources;

use App\Models\Product;
use Lomkit\Rest\Fields\ID;
use Lomkit\Rest\Fields\Integer;
use Lomkit\Rest\Fields\Text;
use Lomkit\Rest\Relations\BelongsTo;

class ProductResource extends Resource
{
    public static string $model = Product::class;

    #[\Override]
    public function fields(): array
    {
        return [
            ID::make('id'),
            Text::make('name')->creationRules('required'),
            Integer::make('price'),
        ];
    }

    #[\Override]
    public function relations(): array
    {
        return [
            BelongsTo::make('category', CategoryResource::class),
        ];
    }
}
```

- `$model` is required and keeps its `string` type. A resource without it throws `Lomkit\Rest\Exceptions\InvalidResourceException`, which names the class. Read it with `ProductResource::modelClass()`.
- Anything that the resource does not declare is refused: a field, a relation, a scope, an action or an instruction that is not in its list gives a `422`.

## What a resource declares

Each declaration is a method that takes no argument and returns a list:

| Method | Returns | Page |
| --- | --- | --- |
| `fields()` | the typed fields that clients read, filter, sort and write | [Fields](/resources/fields) |
| `relations()` | the relations that clients include, filter on and write | [Relationships](/resources/relations) |
| `scopes()` | the model scopes that a search may call | [Scopes and instructions](/search/scopes-and-instructions) |
| `instructions()` | the instructions that a search may apply, listed by their class | [Scopes and instructions](/search/scopes-and-instructions) |
| `actions()` | the actions of the resource | [Actions](/actions-and-metrics/actions) |
| `metrics()` | the metrics of the resource | [Metrics](/actions-and-metrics/metrics) |
| `text()` | the text search strategy, `null` by default | [Text search](/search/text-search) |
| `gates()` | the policy methods that `search.gates` accepts besides the built-in abilities | [Gates](/authorization/gates) |
| `limits()` | the page sizes, `[10, 25, 50]` by default | [Limits](/resources/limits#page-sizes) |
| `rules()`, `createRules()`, `updateRules()` | resource rules for mutations | [Validation](/resources/validation#resource-rules) |
| `defaultOrderBy()` | the order of a search without `sorts`, the model key descending by default | [Sorts and selects](/search/sorts-and-selects) |
| `alwaysSelect()` | columns that every search loads without returning them, `[]` by default | [Fields](/resources/fields#columns-a-search-loads) |
| `detailsMeta()` | keys that the details response returns under `meta` | [Details](/digging-deeper/details) |
| `versioned()` | whether `update` entries send the version of their row, `false` by default | [Versioned rows](/writing/versioned-rows) |

`searchMeta()` adds keys to the `meta` of a search page. It receives the search and the page. See [Responses](/digging-deeper/responses).

The package evaluates each declaration once per request, the first time it reads it, and keeps the result until the request ends. The next request evaluates it again, with its own user.

### Reading the request

A declaration that depends on the user reads the request of the resource with `$this->request()`:

```php
use Lomkit\Rest\Fields\ID;
use Lomkit\Rest\Fields\Integer;
use Lomkit\Rest\Fields\Text;

public function fields(): array
{
    $fields = [ID::make('id'), Text::make('name'), Integer::make('price')];

    if ($this->request()->user()?->is_staff) {
        $fields[] = Integer::make('cost');
    }

    return $fields;
}
```

`$this->request()` returns the request of the endpoint, such as a `SearchRequest` or a `MutateRequest`. `$this->request()->endpoint()` tells which endpoint it is.

### Actions and metrics

`actions()` and `metrics()` list classes, and instances for an action or a metric reused with other settings:

```php
use App\Rest\Actions\CloseTickets;
use App\Rest\Actions\ExportTickets;
use App\Rest\Metrics\TicketBacklog;

public function actions(): array
{
    return [
        CloseTickets::class,
        ExportTickets::make()->middleware('throttle:exports'),
    ];
}

public function metrics(): array
{
    return [TicketBacklog::class];
}
```

- A class carries its configuration in its properties. Registering the routes builds no class, and the container builds it only when it is used, so its constructor can inject services. See [Defining an action](/actions-and-metrics/actions#defining-an-action) and [Metrics](/actions-and-metrics/metrics#defining-a-metric).
- `actions()` creates an instance when the routes register, so its constructor runs then. See [Reusing an action with other settings](/actions-and-metrics/actions#reusing-an-action-with-other-settings).

:::warning
`actions()` and `metrics()` are read when the routes register, at boot and during `php artisan route:cache`, without a user. Return the same actions and metrics for every user, and refuse them to some users with their `abilities()`.
:::

### Instructions

`instructions()` lists classes too, and instances for an instruction built with arguments or reused with other settings:

```php
use App\Rest\Instructions\HeldByInstruction;
use App\Rest\Instructions\UnendedInstruction;

public function instructions(): array
{
    return [
        HeldByInstruction::class,
        UnendedInstruction::make()->meta(['group' => 'dates']),
    ];
}
```

- Registering the routes reads no instruction. The container builds the listed classes the first time a request reads the instructions of the resource, such as a search that sends `instructions` or `/details`, so their constructors can inject services.
- Reading one instruction builds the whole list of the resource, once per request. See [Instructions](/search/scopes-and-instructions#instructions).

### Reading the declarations

`$resource->definition()` returns the declarations of the resource for the current request:

```php
$definition = $resource->definition();

$definition->fields()->names();          // ['id', 'name', 'price']
$definition->relation('category');       // the BelongsTo, or null
$definition->limits()->allowed;          // [10, 25, 50]
```

It also finds one declaration with `relation($name)` (a dotted path is accepted), `scope($name)`, `instruction($key)`, `action($key)` and `metric($key)`.

## Defining a controller

A controller binds a resource to its routes. Controllers live in `app/Rest/Controllers` and extend your base controller, `app/Rest/Controllers/Controller.php`, which extends `Lomkit\Rest\Http\Controllers\Controller`:

```php [app/Rest/Controllers/ProductsController.php]
namespace App\Rest\Controllers;

use App\Rest\Resources\ProductResource;

class ProductsController extends Controller
{
    public static string $resource = ProductResource::class;
}
```

- `$resource` is required and keeps its `string` type. A controller without it throws `Lomkit\Rest\Exceptions\InvalidControllerException` when `Rest::resource()` registers its routes.
- The controller has no hooks: put request-level code in the events of the resource. See [Events and hooks](/digging-deeper/events-and-hooks).

The package controller does not extend Laravel's base controller. Declare middleware with Laravel's `HasMiddleware` interface or with attributes:

```php [app/Rest/Controllers/Controller.php]
namespace App\Rest\Controllers;

use Illuminate\Routing\Controllers\HasMiddleware;
use Illuminate\Routing\Controllers\Middleware;
use Lomkit\Rest\Http\Controllers\Controller as RestController;

abstract class Controller extends RestController implements HasMiddleware
{
    public static function middleware(): array
    {
        return [
            'auth',
            new Middleware('throttle:60,1', only: ['destroy', 'forceDestroy']),
        ];
    }
}
```

```php
use Illuminate\Routing\Attributes\Controllers\Authorize;
use Illuminate\Routing\Attributes\Controllers\Middleware;

#[Middleware('throttle:60,1')]
#[Authorize('manage-products', only: ['destroy', 'forceDestroy'])]
class ProductsController extends Controller
{
    public static string $resource = ProductResource::class;
}
```

## Registering routes

Register the controller in `routes/api.php`:

```php [routes/api.php]
use App\Rest\Controllers\ProductsController;
use Lomkit\Rest\Facades\Rest;

Rest::resource('products', ProductsController::class);
```

`php artisan route:list` shows the routes. With one action, `apply-discount`, under the `api` prefix:

| Method | URI | Name |
| --- | --- | --- |
| `GET\|HEAD` | `api/products` | `products.details` |
| `POST` | `api/products/search` | `products.search` |
| `POST` | `api/products/mutate` | `products.mutate` |
| `POST` | `api/products/actions/apply-discount` | `products.operate.apply-discount` |
| `POST` | `api/products/actions/{action}` | `products.operate` |
| `POST` | `api/products/metrics/{metric}` | `products.metric` |
| `DELETE` | `api/products` | `products.destroy` |

- Each action and each metric gets its own route, before the route of its endpoint. The route `actions/{action}` answers the keys of no action: `403` to a user that `viewAny` refuses, `404` to the others. The route `metrics/{metric}` does the same for metrics.
- The name is one URI segment of letters, digits, `-` and `_`. A dotted name (`users.posts`) or a slashed name (`admin/users`) throws: wrap the call in `Route::prefix('admin')` instead.
- `Rest::resource()` takes two arguments. The routes register when the returned builder is released, or when you call `register()`.
- Every route carries the `EnforceExpectsJson` middleware, so errors come back as JSON even without an `Accept: application/json` header.

:::note
With cached routes, run `php artisan route:cache` again after you add, rename or remove an action or a metric, or change its key or middleware. Each action and metric route records the key and middleware that it was registered with, and an action or a metric built with others throws instead of running. See [Cached routes](/actions-and-metrics/actions#cached-routes).
:::

### Soft deletes

`withSoftDeletes()` adds the `restore` and `forceDestroy` endpoints:

```php
Rest::resource('products', ProductsController::class)->withSoftDeletes();
```

| Method | URI | Name |
| --- | --- | --- |
| `POST` | `api/products/restore` | `products.restore` |
| `DELETE` | `api/products/force` | `products.forceDestroy` |

Pass the endpoints to add only some of them: `withSoftDeletes('restore')`. The model must use `Illuminate\Database\Eloquent\SoftDeletes`, or the registration throws `InvalidResourceException`. See [Deleting](/writing/deleting).

### Choosing endpoints and options

`Rest::resource()` returns a builder. The endpoint keys are `details`, `search`, `mutate`, `operate`, `metric`, `destroy`, `restore`, `forceDestroy` and `batch`, or the cases of `Lomkit\Rest\Http\Routing\Endpoint`. An unknown key throws. The result does not depend on the call order, and repeated calls add up.

```php
Rest::resource('products', ProductsController::class)
    ->except('destroy')                          // or ->only('details', 'search')
    ->withSoftDeletes('restore')                 // restore and forceDestroy, or the ones listed
    ->withBatchProgress()                        // GET products/actions/{action}/batches/{batch}
    ->names('shop.products')                     // name prefix: shop.products.search
    ->name('search', 'products.find')            // exact name of one endpoint
    ->middleware('verified')                     // after the package middleware
    ->middlewareFor('operate', 'throttle:5,1')   // after the resource middleware
    ->withoutMiddleware('verified')              // or ->withoutMiddlewareFor('details', 'verified')
    ->register();
```

- `middleware()` adds to the package middleware. The resource middleware comes before the endpoint middleware, and the endpoint middleware before the middleware of an action.
- `withBatchProgress()` adds the progress route of batched actions. See [Actions](/actions-and-metrics/actions).
- Two endpoints of one resource cannot share a URI or a route name: the registration throws.

### Route groups and verbs

The routes follow the enclosing route groups:

```php
Route::prefix('v2')->name('v2.')->middleware('auth:sanctum')->group(function (): void {
    Rest::resource('products', ProductsController::class);
});
```

Put `where()` or `metadata()` on the enclosing group. `Route::resourceVerbs()` renames the URI segments through the keys `search`, `mutate`, `actions`, `metrics`, `restore` and `forceDestroy`:

```php
Route::resourceVerbs(['search' => 'find', 'forceDestroy' => 'purge']);
```

### Test suites

Every test boots the application again and registers the routes again, which builds every resource. Add Laravel's `WithCachedRoutes` trait to your base test case:

```php [tests/TestCase.php]
use Illuminate\Foundation\Testing\TestCase as BaseTestCase;
use Illuminate\Foundation\Testing\WithCachedRoutes;

abstract class TestCase extends BaseTestCase
{
    use WithCachedRoutes;
}
```

- The first test compiles the routes in memory, and the following tests receive them before the application boots: the route files, `Rest::resource()` included, no longer run between tests.
- The routes of the first test serve the whole suite. A test that needs other routes, such as one that changes `actions()` or calls `Rest::resource()` itself, extends a base test case without the trait.
- With the trait, a route registered after the application booted, by a test or by the provider of a test fixture, is matched by URL. `route('name')`, `Route::has()` and the lookups by name or by action can miss it, because Laravel does not refresh these lookups on compiled routes: register such routes in a test case without the trait.

## Base classes

`app/Rest/Resources/Resource.php` and `app/Rest/Controllers/Controller.php` hold what every resource or controller shares: a `perimeterQuery()` that scopes every resource to the team of the user, the middleware of every controller, or the page sizes of every resource.

```php [app/Rest/Resources/Resource.php]
namespace App\Rest\Resources;

use Lomkit\Rest\Http\Resource as RestResource;

abstract class Resource extends RestResource
{
    public int $includeLimit = 25;

    #[\Override]
    public function limits(): array
    {
        return [10, 25, 50, 100];
    }
}
```

`rest:resource` and `rest:controller` create the base classes when they are missing. `rest:base-resource` and `rest:base-controller` create them on their own.

## Generating a resource

Generate a resource and a controller:

```bash
php artisan rest:resource ProductResource --model=Product
php artisan rest:controller ProductsController --resource=ProductResource
```

Without `--model`, the model is guessed from the name: `ProductResource` gives `App\Models\Product`, and `Admin/ProductResource` gives `App\Models\Admin\Product`. Without `--resource`, `ProductsController` gives `App\Rest\Resources\ProductResource`. An existing class is kept unless you pass `--force`.

### From the table of the model

`--generate` (`-G`) reads the table of the model and declares one field per column, then one relation per relation method of the model whose related model has a resource. Run it after the migrations:

```bash
php artisan rest:resource ArticleResource --model=Article --generate
```

An excerpt of the generated `fields()`:

```php
public function fields(): array
{
    return [
        ID::make('id'),
        // ...
        Text::make('title')
            ->rules('max:255')
            ->creationRules('required'),
        Text::make('slug')
            ->rules('max:120')
            ->creationRules('required', Rule::unique(Article::class, 'slug'))
            ->updateRules(Contextual::rule(fn (MutationContext $mutation) => Rule::unique(Article::class, 'slug')->ignore($mutation->key))),
        Text::make('summary')->nullable(),
        Enum::make('status'),
        Boolean::make('featured'),
        Date::make('published_on')->nullable(),
        Json::make('metadata')->nullable(),
        Text::make('editor_token')
            ->nullable()
            ->writeOnly()
            ->rules('max:255'),
        DateTime::make('created_at')
            ->nullable()
            ->readonly(),
        DateTime::make('updated_at')
            ->nullable()
            ->readonly(),
    ];
}
```

Each column gives one field:

- the key of the model gives `ID`, with `creatable()` when the key is neither incrementing nor generated by `HasUuids` or `HasUlids`;
- a cast gives its type: a backed enum `Enum`, the JSON casts `Json`, `boolean`, `integer`, `decimal`, `float`, `date` and `datetime` their field type. Otherwise the column type decides, and an unknown type gives `Text` with a note;
- a nullable column gets `nullable()`;
- the timestamps, the auto-increment and generated columns, the columns that `HasUuids` or `HasUlids` fill, and the foreign key of a generated `BelongsTo` get `readonly()`;
- a column that the authentication flow writes is left out with a note: `remember_token` (or the `getRememberTokenName()` of an `Authenticatable` model), `two_factor_secret`, `two_factor_recovery_codes` and `two_factor_confirmed_at`. `password` keeps its field;
- a hidden column gets `writeOnly()`, and a hidden column that the model does not let fill is left out with a note;
- a `Text` or `ID` field whose column has a length that the database reports gets `rules('max:<length>')`. MySQL and PostgreSQL report it, SQLite does not;
- a column that is not nullable and has no default gets `creationRules('required')`;
- a column with its own unique index gets `Rule::unique()` on creation, and on update a rule that ignores the row being updated, built with [`Contextual::rule()`](/resources/validation#rules-that-depend-on-the-entry);
- a column with an `encrypted` cast gets `filterable(false)` and `sortable(false)`, since the database holds its value encrypted.

```php
Text::make('diagnosis')
    ->nullable()
    ->filterable(false)
    ->sortable(false),
```

Each relation method with a declared Eloquent return type, such as `public function author(): BelongsTo`, gives the relation class of the same name when the related model has a resource. A `BelongsTo` whose foreign key is required gets `requiredOnCreation()`, and a many-to-many relation gets the pivot fields of its `withPivot()` columns. A relation whose `detach` would set to null a column that does not accept null gets `->withoutOperations(MutationOperation::Detach)`: the foreign key of a `BelongsTo` in the table of the model, or the foreign key or morph type of a `HasOne`, `HasMany`, `MorphOne` or `MorphMany` in the related table. See [Link columns that do not accept null](/resources/relations#link-columns-that-do-not-accept-null).

```php
BelongsTo::make('desk', DeskResource::class)
    ->requiredOnCreation()
    ->withoutOperations(MutationOperation::Detach),
HasMany::make('comments', CommentResource::class)->withoutOperations(MutationOperation::Detach),
``` A relation to a model without a resource, and a `MorphTo`, are skipped with a line that says what to do. The line of a `MorphTo` names its real targets: the resources of the models of the morph map whose `morphOne()`, `morphMany()` or `morphToMany()` relation points back to it:

```text
  Skipped: commentable: MorphTo relations are not generated, declare it in relations() by hand with its targets, for example MorphTo::make('commentable', [PostResource::class, VideoResource::class]).
```

Without such a model, the line ends after `with its targets.`

After the `created successfully` line, the command prints the resource with its counts of fields and relations, then one `Skipped:` line for each relation that it did not generate and one `Note:` line for each column that needs a check:

```text
  Skipped: author: no resource for App\Models\User. Generate one first with php artisan rest:resource UserResource --model=User --generate, then run this command again with --force.
```

The foreign key of a skipped relation stays a writable field.

:::tip
Check the generated fields before you expose the resource: hide a column with `writeOnly()` or remove it, and adjust the rules.
:::

Interactively, without `--generate`, the command asks `Generate the fields and relations from the <table> table?` when the table exists. With `--no-interaction` and without `--generate`, the resource declares only its key.
