## Overview

Version 3.0 types every declaration, validates every payload against these types, and reads each request through one perimeter and one set of policy checks. Most applications change their resources more than their clients: fields become objects, the request argument of the declarations goes away, and the query hooks become one `perimeterQuery()`.

This page summarizes the changes by area and links to the page that documents each one. The package's [UPGRADE.md](https://github.com/Lomkit/laravel-rest-api/blob/3.x/UPGRADE.md) lists every change, with the exact messages and the edge cases: read it before you deploy.

:::tip
PHP stops on a class whose override keeps an old signature, and names the method. Run your test suite and `php artisan route:list` after each step: most of the upgrade is driven by these errors.
:::

## Requirements

- PHP **8.3** or higher, and Laravel **13.30** or higher. Applications on Laravel 12 stay on 2.x.
- Laravel Scout **11.9** or higher, when Scout is installed.
- Scramble `^0.13.48` for the OpenAPI document.

See [Installation](/getting-started/installation).

## Configuration

Compare your published `config/rest.php` with the package file, then:

- Remove `authorizations.enabled` and `gates.enabled`. Override `isAuthorizingEnabled()` or `isGatingEnabled()` on your base resource and return `false` instead.
- Remove `authorizations.cache.default`. Each resource declares the seconds of each ability in `authorizationCache()`.
- Remove `gates.message.enabled`: each gate answer now holds `allowed` and `message`.
- Move `search.max_nesting_depth` to `limits.depths.filters`.
- Remove the `documentation` block.
- New keys: `authorizations.strict`, `authorizations.cache.store`, `morph.type_key`, `search.select_columns`, `search.more_key`, `transactions.attempts` and the `limits` block.
- The defaults now merge into your file at every level, and each value is type-checked: a wrong type throws an exception that names the key.

See [Configuration](/getting-started/configuration).

## Routing

- `Rest::resource()` takes two arguments. Replace the `$options` array with `only()`, `except()`, `names()`, `middleware()` and `withSoftDeletes()`. A forgotten third argument is ignored.
- The resource name is one URI segment. Wrap the call in `Route::prefix('admin')` instead of `admin/users`.
- `middleware()` adds to the package middleware instead of replacing it.
- Each action and each metric has its own route, named `{name}.operate.{uriKey}` and `{name}.metric.{uriKey}`. `actions()` and `metrics()` are read when the routes register: return the same list for every user, and run `php artisan route:cache` again after a change.
- The force delete endpoint is named `forceDestroy`: route name `{name}.forceDestroy`, controller method `forceDestroy()`. The URI stays `{name}/force`.
- `withSoftDeletes()` throws when the model does not use `SoftDeletes`.

See [Resources](/resources/resources#registering-routes).

## Resources and controllers

- `$model` and `$resource` are typed: `public static string $model = Post::class;`.
- The declarations take no argument: `fields()`, `relations()`, `scopes()`, `limits()`, `actions()`, `instructions()`, `rules()`, `createRules()`, `updateRules()`, `defaultOrderBy()` and the others. Read the request with `$this->request()`.
- The declarations are evaluated once per request. Read them with `$resource->definition()`: `getFields()`, `getRelations()` and the other getters are removed.
- The controller hooks are removed. Move their code to the endpoint events of the resource, such as `searching()` and `mutatedAll()`. See [Events and hooks](/digging-deeper/events-and-hooks).
- `Controller` no longer extends Laravel's controller: declare middleware with `HasMiddleware` or the `#[Middleware]` attribute.

See [Resources](/resources/resources).

## Fields

- `fields()` returns typed field objects instead of column names: `ID`, `Text`, `Integer`, `Number`, `Boolean`, `Date`, `DateTime`, `Enum` and `Json`. Add `->nullable()` to nullable columns.
- A field decides how it is selected, sorted, filtered and written: `readonly()`, `writeOnly()`, `virtual()`, `selectable()`, `sortable()`, `filterable()`, `creatable()`, `updatable()`, `resolveUsing()`, `fillUsing()`.
- The `ID` field and `readonly()` fields are refused in `attributes`. Declare `->creatable()` on a key that clients send.
- A search loads only the columns its rows need. A policy or a custom response that reads another column needs it in `alwaysSelect()`, or in the `requires()` of a field.
- The appended attributes of a model are no longer returned. Use a `virtual()` field with `resolveUsing()`.

See [Fields](/resources/fields).

## Scopes, instructions and actions inputs

- `scopes()` returns `Scope` objects, and their parameters are typed fields, bound by position.
- The `fields()` of instructions and actions return typed fields instead of rule maps.
- `handle()` receives an `ActionFields` or `InstructionFields` object instead of an array: `$fields->plan` instead of `$fields['plan']`.

See [Scopes and instructions](/search/scopes-and-instructions) and [Actions](/actions-and-metrics/actions).

## Relations

- `withPivotFields()` and `withPivotRules()` are replaced by `pivotFields([...])` with typed fields.
- `MorphTo` declares its targets: `MorphTo::make('labelable', [BookResource::class, ShelfResource::class])`. Each row of a `MorphTo` include starts with its `@type`.
- The callbacks of `requiredOnCreation()` and the other constraints receive the request and the related resource.
- `sync` and `toggle` are accepted on many-to-many relations only. Through relations take no entry.
- Child relations can delete rows in a mutation once they declare `deletable()`. See [Deleting child rows](/resources/relations#deleting-child-rows).

See [Relationships](/resources/relations).

## Validation

- Every payload is validated in one pass, with rules on explicit keys such as `search.filters.0.field` and `mutate.0.attributes.name`.
- A key that the package does not know inside an object of a payload gives a `422`: `The search.filters.0.operater field is prohibited.` Unknown keys at the first level stay ignored.
- The field rules apply to mutations: `null` is refused unless the field is `nullable()`.
- Fields take `label()` and `messages()`.
- Every list, depth and total is limited by `rest.limits`.
- Keys are typed by the `ID` field, and checked through `perimeterQuery()`.

See [Validation](/resources/validation) and [Limits](/resources/limits).

## Perimeter

- `searchQuery()` is renamed `perimeterQuery()` and applies to every endpoint, at every level of a request.
- `mutateQuery()`, `destroyQuery()`, `restoreQuery()` and `forceDeleteQuery()` are removed. Move their conditions to a policy or to `perimeterQuery()`.
- `perimeterQuery()` takes the builder only and declares its return type.

See [Perimeter](/resources/perimeter).

## Authorization

- Each request checks `viewAny` on its endpoint and on every resource its payload reaches before validation: a `403` now comes before a `422`.
- Each created row is checked with its draft, and each updated row with its `Changes`.
- The links of a relation are checked with the abilities it declares, `->abilities(attach: 'attachTag', detach: 'detachTag')`, or with `update` on the parent.
- The decision cache keeps only the abilities a resource declares in `authorizationCache()`.
- `authorizations.strict` reports a check that the request did not plan.

See [Policies](/authorization/policies), [Gates](/authorization/gates) and [Decision cache](/authorization/decision-cache).

## Search

- An include returns at most its `limit` rows per parent, or the `$includeLimit` of its resource, 10 by default. `@more` tells which lists are cut.
- `=` and `!=` with `null` give a `422`: use `is null` and `is not null` on a nullable field.
- The operators depend on the type of the field. `ilike`, `between`, `is null` and relation groups are new.
- Every order ends with the model key.
- A text search is declared with `text()`: `Contains`, `FullText` or `ScoutEngine`. A Scout model no longer gives its resource a text search by itself.
- `searchMeta()` on a resource adds keys to the `meta` of a search page, see [Meta](/search/overview#meta). On an instruction, it adds an object under `meta.instructions`, see [Instruction meta](/search/scopes-and-instructions#instruction-meta).
- `Rest::search()` runs a search outside HTTP, and `lazy()` reads every row of it for an export. See [Searching outside HTTP](/search/outside-http).

See [Search](/search/overview), [Filters](/search/filters), [Text search](/search/text-search), [Search engines](/search/search-engines) and [Searching outside HTTP](/search/outside-http).

## Writes

- The mutate endpoint answers `operations` instead of `created` and `updated`, and returns the written rows with a `response` block.
- Versioned rows are new: the `update` entries of a `versioned()` resource accept the `version` that the client read, and the mutation answers `409` and writes nothing when the row changed since. See [Versioned rows](/writing/versioned-rows).
- Writes run in one transaction on the connection of the model, and can run again on a deadlock.
- The keys that a parent relation sets win over the attributes of the entry.
- `destroy`, `restore` and `forceDestroy` check every row before they write any, and write them in one transaction.

See [Mutate](/writing/mutate), [Writing relations](/writing/relations), [Versioned rows](/writing/versioned-rows) and [Deleting](/writing/deleting).

## Responses

- `meta` and `pivot` are objects, `{}` when empty.
- Each gate answer is `{"allowed": ..., "message": ...}`.
- A row returns the relations that its search includes, and no other.
- A custom `Response` keeps `map()` only.

See [Responses](/digging-deeper/responses).

## Details

- The details endpoint answers a thin base: `fields` with their `name`, `label`, `type` and `nullable`, `limits` and `meta`. Ask for the rest with the `with` query parameter, such as `GET /api/products?with=fields.capabilities,relations.operations,authorizations`. What is not asked for is not computed. See [Asking for more with `with`](/digging-deeper/details#asking-for-more-with-with).
- The entries are typed: fields with their capabilities and rules, relations with their operations, inputs, text search, gates and authorizations.
- `actions.authorized` and `metrics.authorized` tell whether the user may run each action and metric.

See [Details](/digging-deeper/details).

## Actions, events and metrics

- Actions choose their rows with `ActionTarget` instead of `standalone()` and `targeted()`, and can answer with a result, ask for a confirmation with a `428` answer and check each row.
- Queued actions run in the worker as the user who sent the request.
- The controller hooks are replaced by resource events, and writes dispatch Laravel events.
- Metrics are new.

See [Actions](/actions-and-metrics/actions), [Confirmation](/actions-and-metrics/confirmation), [Metrics](/actions-and-metrics/metrics) and [Events and hooks](/digging-deeper/events-and-hooks).

## OpenAPI

- The built-in documentation generator is removed, with the `/api-documentation` route, `rest:documentation` and `Rest::withDocumentationCallback()`.
- Install Scramble: the package registers its documentation itself, and documents every endpoint from the declarations.

See [OpenAPI](/digging-deeper/openapi).

## Generators

- The generated classes are typed and pass Larastan at level 10. Delete or republish the stubs that you published under 2.x: their untyped properties are a fatal error in 3.0.
- `rest:resource --generate` declares the fields and relations from the table of the model.
- `rest:policy` and `rest:metric` are new, and `rest:quick-start` asks which models to expose.

See [Resources](/resources/resources#generating-a-resource) and [Artisan](/digging-deeper/artisan).

## Removed features

| Removed | Replacement |
| --- | --- |
| `authorizations.enabled`, `gates.enabled` | `isAuthorizingEnabled()`, `isGatingEnabled()` |
| `DisableAuthorizations`, `DisableGates`, `DisableAuthorizationsCache` traits | the methods above, `authorizationCache()` |
| `searchQuery()` | `perimeterQuery()` |
| `mutateQuery()`, `destroyQuery()`, `restoreQuery()`, `forceDeleteQuery()` | `perimeterQuery()` or a policy |
| controller hooks (`beforeSearch()`, `afterMutate()`, ...) | resource events |
| `withPivotFields()`, `withPivotRules()` | `pivotFields()` |
| `standalone()`, `targeted()` | `ActionTarget` |
| `scoutFields()`, `scoutInstructions()`, `searchScoutQuery()` | `ScoutEngine::make()` in `text()` |
| `Lomkit\Rest\Query\Builder` and its binding | `perimeterQuery()`, model scopes, `searching()` |
| built-in OpenAPI generator, `/api-documentation` | Scramble |
| `lomkit-rest` container alias | `Lomkit\Rest\Rest` or the `Rest` facade |

## Steps

1. Update PHP and Laravel, then run `composer require lomkit/laravel-rest-api:^3.0`.
2. Update `config/rest.php`.
3. Type `$model` and `$resource`, remove the request parameter of every declaration, and replace the field names with field objects.
4. Rename `searchQuery()` to `perimeterQuery()` and move the other query hooks.
5. Move the controller hooks to the resource events.
6. Update the actions, the instructions and the scopes.
7. Run the queued actions of 2.x before you deploy: a job queued before the upgrade cannot run after it.
8. Update the clients: the `operations` response of `mutate`, the gate answers, `is null` filters, include limits and the `MorphTo` declarations.
