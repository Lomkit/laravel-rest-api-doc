## What it is

Laravel Rest Api turns your Eloquent models into a full API without one controller per use case. For each model, you write a **resource** that declares what the API exposes: its fields, its relations, its scopes, its actions and its rules. A thin **controller** binds the resource to a route name, and one call to `Rest::resource()` registers its endpoints.

```php [app/Rest/Resources/ProductResource.php]
namespace App\Rest\Resources;

use App\Models\Product;
use Lomkit\Rest\Fields\ID;
use Lomkit\Rest\Fields\Integer;
use Lomkit\Rest\Fields\Text;
use Lomkit\Rest\Relations\BelongsTo;

class ProductResource extends Resource
{
    public static string $model = Product::class;

    public function fields(): array
    {
        return [
            ID::make('id'),
            Text::make('name')->creationRules('required'),
            Integer::make('price'),
        ];
    }

    public function relations(): array
    {
        return [
            BelongsTo::make('category', CategoryResource::class),
        ];
    }
}
```

```php [routes/api.php]
use App\Rest\Controllers\ProductsController;
use Lomkit\Rest\Facades\Rest;

Rest::resource('products', ProductsController::class);
```

Clients can now search, filter, sort and paginate the products, include their category, create and update them in batches, and delete them, all inside the rules you declared.

## The endpoints

Each registered resource answers on a fixed set of routes:

| Method | URI | Endpoint | Purpose |
| --- | --- | --- | --- |
| `GET` | `/api/products` | `details` | Describe the resource for the current user |
| `POST` | `/api/products/search` | `search` | Filter, sort, include, aggregate and paginate rows |
| `POST` | `/api/products/mutate` | `mutate` | Create and update rows and their relations in one transaction |
| `POST` | `/api/products/actions/{action}` | `operate` | Run an action that the resource declares |
| `POST` | `/api/products/metrics/{metric}` | `metric` | Compute a metric that the resource declares |
| `DELETE` | `/api/products` | `destroy` | Delete rows |
| `POST` | `/api/products/restore` | `restore` | Restore soft-deleted rows, opt-in |
| `DELETE` | `/api/products/force` | `forceDestroy` | Force delete rows, opt-in |

See [Resources](/resources/resources) for the registration options.

## Why use it

- **Declare, do not code.** A column that a resource does not declare does not exist for clients. The same goes for relations, scopes, actions and instructions. Adding a column to a table never exposes it.
- **One request, many rows.** A search reads nested relations with their own filters and limits. A mutation creates a row, attaches its tags and updates its children in one transaction.
- **Authorization built in.** Every endpoint checks your Laravel policies: `viewAny` on each resource a request reaches, then each row it writes or deletes. A perimeter query decides which rows exist for each client. See [Perimeter](/resources/perimeter) and [Policies](/authorization/policies).
- **Typed and validated.** Each field has a type that decides its filter operators, its validation and its OpenAPI schema. Every payload is validated in one pass, with exact error keys such as `search.filters.0.field`.
- **Bounded.** Request sizes, nesting depths and totals are limited by configuration, so one request cannot ask for unbounded work. See [Limits](/resources/limits).
- **Documented.** The package describes every endpoint in the OpenAPI document that Scramble serves. See [OpenAPI](/digging-deeper/openapi).

## How it fits Laravel

The package builds on what your application already has:

- **Eloquent**: resources read and write your models, their casts, their scopes and their relations.
- **Policies**: authorization goes through `Gate` and your policy classes. See [Policies](/authorization/policies).
- **Validation**: field rules are Laravel rules, and errors come back as standard `422` responses. See [Validation](/resources/validation).
- **Routing**: `Rest::resource()` registers plain Laravel routes that work with route groups, middleware, `route:list` and `route:cache`.
- **Queues and events**: actions can be queued or batched, and writes dispatch Laravel events. See [Actions](/actions-and-metrics/actions) and [Events and hooks](/digging-deeper/events-and-hooks).
- **Laravel Scout**: a resource can run its text search on a Scout search engine. See [Search engines](/search/search-engines).
- **Laravel Precognition**: forms can validate a payload before they send it. See [Precognition](/digging-deeper/precognition).
