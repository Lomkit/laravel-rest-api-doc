The package ships generators for each class it uses. The classes they write pass Pint with the `laravel` preset and Larastan at level 10: they import the classes they use and mark each overriding method with `#[\Override]`.

| Command | Writes |
|---|---|
| `rest:quick-start` | the resources, controllers, policies and routes of the models you choose |
| `rest:resource PostResource --model=Post` | `app/Rest/Resources/PostResource.php` |
| `rest:controller PostsController --resource=PostResource` | `app/Rest/Controllers/PostsController.php` |
| `rest:policy PostPolicy --model=Post` | `app/Policies/PostPolicy.php` |
| `rest:action ExtendSubscriptions` | `app/Rest/Actions/ExtendSubscriptions.php` |
| `rest:instruction OddEvenId` | `app/Rest/Instructions/OddEvenId.php` |
| `rest:metric OrdersByStatus --type=partition --group-by=status` | `app/Rest/Metrics/OrdersByStatus.php` |
| `rest:response ArticleResponse` | `app/Rest/Responses/ArticleResponse.php` |
| `rest:base-resource`, `rest:base-controller` | the abstract base classes `app/Rest/Resources/Resource.php` and `app/Rest/Controllers/Controller.php` |

Every generator keeps an existing class: it prints `<Type> already exists.` and exits with `0`. Pass `--force` (`-f`) to replace it.

## Quick start

`rest:quick-start` asks which models to expose, then writes their resources from their tables, their controllers, a policy that allows every ability when Gate finds none, and one route per model behind the `auth` middleware of the guard, `auth:sanctum` by default. It checks the result in a new process before it reports success.

```bash
php artisan rest:quick-start
php artisan rest:quick-start --no-interaction --model=Post --model=Tag --install-api
```

See [Quick start](/getting-started/quick-start) for every option.

## Resources

```bash
php artisan rest:resource PostResource --model=Post --generate
```

- Without `--model`, the model is guessed from the class name: `PostResource` gives `App\Models\Post` when that class exists.
- The key field is `ID::make()` with the key name of the model.
- `rest:resource` creates the base resource when it is missing.

### Generating the fields and relations

`--generate` (`-G`) reads the table of the model and declares one field per column, in the order of the table, then one relation per relation method whose related model has a resource. Run it after the migrations.

```
PostResource ... 8 fields, 1 relation
Skipped: author: no resource for App\Models\User. Generate one first with php artisan rest:resource UserResource --model=User --generate, then run this command again with --force.
```

- A cast gives the field type when one matches: a backed enum gives `Enum`, the JSON casts give `Json`, `boolean`, `integer`, `decimal`, `float`, `date` and `datetime` give `Boolean`, `Integer`, `Number`, `Date` and `DateTime`. Otherwise the column type decides.
- A nullable column gets `nullable()`. The timestamps, auto-increment and generated columns get `readonly()`. A hidden column gets `writeOnly()`.
- A string column whose length the database reports gets `rules('max:<length>')`. A column that is not nullable and has no default gets `creationRules('required')`, and a column with a unique index gets `Rule::unique()`.
- A generated `BelongsTo` relation makes its foreign key `readonly()`, so clients set it through the relation.
- A `MorphTo` relation is skipped, with a note that prints the declaration to write by hand.
- A many-to-many relation with `withPivot()` columns gets `pivotFields([...])`.

When the command runs interactively without `--generate` and the table exists, it asks `Generate the fields and relations from the <table> table?`. Read the generated fields before you expose the resource.

## Controllers

```bash
php artisan rest:controller PostsController --resource=PostResource
```

Without `--resource`, the resource is guessed: `PostsController` gives `App\Rest\Resources\PostResource`. When nothing is found, the `$resource` line is left out and the command warns: set it before `Rest::resource()` registers the controller.

## Policies

```bash
php artisan rest:policy PostPolicy --model=Post
```

The policy allows every ability to a signed-in user: `viewAny()`, `view()`, `create()`, `update()` and `delete()`, plus `restore()` and `forceDelete()` for a model that uses `SoftDeletes`. The user parameter has the type of the user model of the default guard.

When Gate already finds another policy for the model, the command prints `The model [App\Models\Post] already has the policy [App\Policies\ContentPolicy].` and writes nothing.

:::warning
Edit the generated policy before production. See [Policies](/authorization/policies).
:::

## Metrics

```bash
php artisan rest:metric OrdersByStatus --type=partition --group-by=status
```

| `--type` | `calculate()` returns |
|---|---|
| `value` | `$this->count($query)`, without ranges |
| `trend` | `$this->countByDays($query)`, with the ranges 7, 30 and 90 days |
| `partition` | `$this->count($query, '<group-by>')` |
| `progress` | `$this->count($query, target: 100)` |
| `table` | `$this->rows($query, '<group-by>', ['count' => TableColumn::count()])` |
| `custom` | a `ValueResult`, in a class that extends `Metric` |

`--group-by` is required for `partition` and `table`. With `--no-interaction`, a metric without `--type` is a `value` metric. See [Metrics](/actions-and-metrics/metrics).

## Actions, instructions and responses

- `rest:action` writes an action with `handle(ActionFields $fields, Collection $models)` and a `fields()` method that returns `[]`. It has the `Search` target. See [Actions](/actions-and-metrics/actions).
- `rest:instruction` writes an instruction with `handle(InstructionFields $fields, Builder $query)`. See [Scopes and instructions](/search/scopes-and-instructions).
- `rest:response` writes a response with its `map()` method. See [Custom responses](/digging-deeper/responses).

## Published stubs

The generators read the stubs that `php artisan stub:publish` copies to `stubs/rest.<name>.stub`, and fall back to the package stubs. A published stub keeps the placeholders that the generator fills, such as `{{ namespace }}` and `{{ class }}`. A missing placeholder throws `Lomkit\Rest\Exceptions\InvalidStubException`, which names the stub and the placeholder.

`rest:metric` reads one stub per type: `rest.metric-value.stub`, `rest.metric-trend.stub`, `rest.metric-partition.stub`, `rest.metric-progress.stub`, `rest.metric-table.stub`, and `rest.metric.stub` for `custom`.
